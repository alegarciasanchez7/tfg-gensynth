# GenSynth Connector Plugin Developer Guide

A **connector** decides *where* the messages generated by a flow go: a message broker, a socket,
a file, a database, an HTTP endpoint… GenSynth generates each message from the flow's message
format and hands it to the flow's connector, which sends it.

This guide explains how to write a connector plugin for any technology (Kafka, AMQP, MQTT, TCP,
UDP, HTTP…). It is not a recipe for one technology: it describes the contract every plugin follows.

A plugin only has to do two things:

1. **Declare the fields it needs** (host, topic, credentials…), in the order they are shown.
   GenSynth builds the connector section of the flow configuration from them, validates the
   values and applies defaults.
2. **Implement the connection**: open it, send one message, close it.

Everything else (scheduling, threads, retries of the simulation, metrics, UI, persistence) is
done by GenSynth.

---

## 1. Quick start

```java
package com.example.gensynth.udp;

import com.gensynth.plugin.api.*;

import java.net.DatagramPacket;
import java.net.DatagramSocket;
import java.net.InetAddress;
import java.util.List;
import java.util.Map;

public class UdpConnectorPlugin implements ConnectorPlugin {

    @Override
    public ConnectorInfo info() {
        return new ConnectorInfo("udp", "UDP", "1.0.0", "Sends each message as one UDP datagram.");
    }

    @Override
    public List<ConnectorField> fields() {
        return List.of(
            ConnectorField.text("host").label("Host").required().defaultValue("localhost")
                .tooltip("Host name or IP address that receives the datagrams."),
            ConnectorField.integer("port").label("Port").required().min(1).max(65535)
                .tooltip("UDP port of the receiver.")
        );
    }

    @Override
    public ConnectorSession connect(ConnectorConfig config, ConnectorContext context) throws Exception {
        InetAddress address = InetAddress.getByName(config.getString("host"));
        int port = config.getInt("port", 0);
        DatagramSocket socket = new DatagramSocket();
        return new ConnectorSession() {
            @Override
            public void send(byte[] payload, Map<String, String> headers) throws Exception {
                socket.send(new DatagramPacket(payload, payload.length, address, port));
            }

            @Override
            public void close() {
                socket.close();
            }
        };
    }
}
```

Register it in `src/main/resources/META-INF/services/com.gensynth.plugin.api.ConnectorPlugin`:

```
com.example.gensynth.udp.UdpConnectorPlugin
```

Build the JAR, and import it from **Connectors → Import plugin** in GenSynth. That's it: the
"UDP" connector appears in the connector selector of every flow, with a *Host* and a *Port* field.

> Note: this example uses `java.net.DatagramSocket`, which the plugin sandbox blocks (see §8).
> It only illustrates the shape of a plugin; a real UDP plugin would need that API to be allowed.

## 2. Project setup

A plugin is a plain Java 21 JAR. It depends on the GenSynth plugin API with **`provided`**
scope: GenSynth supplies the API at runtime, so it must never be bundled in your JAR.

```xml
<dependencies>
    <dependency>
        <groupId>com.gensynth</groupId>
        <artifactId>gensynth-plugin-api</artifactId>
        <version>1.0.0</version>
        <scope>provided</scope>
    </dependency>

    <!-- The client library of your technology (see "Dependencies" below) -->

    <dependency>
        <groupId>junit</groupId>
        <artifactId>junit</artifactId>
        <version>4.13.2</version>
        <scope>test</scope>
    </dependency>
</dependencies>
```

To get the API in your local Maven repository, run `mvn install` in the `plugin-api/` folder of
the GenSynth repository (or at the repository root, which builds everything).

Recommended layout:

```
my-plugin/
├── pom.xml
└── src/
    ├── main/java/<your package>/MyConnectorPlugin.java
    ├── main/java/<your package>/MySession.java          (optional, if the session is large)
    ├── main/resources/META-INF/services/com.gensynth.plugin.api.ConnectorPlugin
    └── test/java/<your package>/MyConnectorPluginTest.java
```

Use your own package (e.g. `com.example.gensynth.mqtt`), not `com.gensynth.core`.

### Dependencies

Your plugin runs in its own class loader. It can see:

- the plugin API (`com.gensynth.plugin.api`), shared with GenSynth;
- the Java platform and `org.slf4j` (for logging);
- the client libraries shipped in GenSynth's `core/lib/shared` folder: `kafka-clients`,
  `amqp-client` (RabbitMQ), `org.eclipse.paho.client.mqttv3` (MQTT), `activemq-client`,
  `pulsar-client`, `jnats` (NATS) and `jedis` (Redis);
- the classes of your own JAR.

If your client library is in `lib/shared`, declare it with `provided` scope and your JAR stays
tiny. Otherwise, **bundle it** in your JAR with the `maven-shade-plugin` (and keep the plugin API
out of the shaded JAR, which `provided` scope already does).

## 3. The API at a glance

| Type | Role |
|---|---|
| `ConnectorPlugin` | The class you implement: `info()`, `fields()`, `connect(...)`. |
| `ConnectorInfo` | Identity: `id`, `displayName`, `version`, `description`. |
| `ConnectorField` | One configuration field: type, label, tooltip, required, default... |
| `FieldType` | `TEXT`, `PASSWORD`, `INTEGER`, `DECIMAL`, `BOOLEAN`, `SELECT`. |
| `ConnectorConfig` | The validated field values received by `connect`. |
| `ConnectorContext` | Runtime info about the flow: flow name, group name, session folder. |
| `ConnectorSession` | An open connection: `send(...)`, `close()`, `isHealthy()`. |
| `PluginApi` | The API version (`PluginApi.VERSION`) and the service file name. |

### 3.1 `ConnectorPlugin`

```java
public interface ConnectorPlugin {
    ConnectorInfo info();
    List<ConnectorField> fields();
    ConnectorSession connect(ConnectorConfig config, ConnectorContext context) throws Exception;
}
```

- Needs a **public no-argument constructor** (ServiceLoader creates it).
- Should be **stateless**: GenSynth creates one instance and calls `connect` once per flow.
  Keep `info()` and `fields()` cheap; returning constants is ideal.

### 3.2 `ConnectorInfo`

```java
new ConnectorInfo("mqtt", "MQTT", "1.0.0", "Publishes each message to an MQTT topic.");
```

- `id`: lowercase letters, digits, `.`, `_`, `-`. It is stored in every project file that uses
  the connector, so **never change it**.
- `displayName`: shown in the connector selector.
- `version`: the version of *your plugin* (not of the technology). Use semantic versioning;
  GenSynth uses the highest installed version of each `id`.
- `description`: one sentence, shown in the connector section and in the connectors panel.

## 4. Declaring fields

Fields are built fluently. Every method returns a new, immutable field:

```java
ConnectorField.text("host")                // factory: key and type
    .label("Host")                          // text next to the input (default: key in words)
    .tooltip("Broker host name or IP.")     // help shown on the info icon
    .placeholder("localhost")               // hint inside an empty input
    .defaultValue("localhost")              // used when the user leaves it empty
    .required();                            // must have a value
```

| Factory | Input in the UI | Value type in `ConnectorConfig` |
|---|---|---|
| `text(key)` | text box | `String` → `getString` |
| `password(key)` | masked text box with show/hide | `String` → `getString` |
| `integer(key)` | number box (whole numbers) | `long` → `getInt` / `getLong` |
| `decimal(key)` | number box | `double` → `getDouble` |
| `bool(key)` | switch (default `false`) | `boolean` → `getBoolean` |
| `select(key, Option...)` / `select(key, String...)` | drop-down | `String` → `getString` |

Numeric fields accept `.min(...)` and `.max(...)`. Select fields default to their first option:

```java
ConnectorField.select("qos",
        ConnectorField.Option.of("0", "0: at most once"),
        ConnectorField.Option.of("1", "1: at least once"),
        ConnectorField.Option.of("2", "2: exactly once"))
    .label("Quality of service")
    .defaultValue("1")
    .tooltip("Delivery guarantee requested from the broker.");
```

### Guidelines for good fields

- **Order matters**: list them as a user thinks about the connection: where (host, port),
  who (credentials), what (topic/queue/key), then optional tuning.
- **Every field gets a tooltip.** Say what the value is, give an example, and mention any trap
  (e.g. "the default `guest` user only works from localhost").
- Mark as `required()` only what the connection really cannot work without. Prefer sensible
  defaults for everything else.
- Use `password(...)` for every secret.
- **Keys are part of saved projects.** Renaming a key loses the value of existing flows; add a
  new key instead and keep reading the old one if needed.
- Rules that involve several fields (e.g. "routing key is required unless the exchange is
  fanout") cannot be expressed per field: check them at the start of `connect` and throw an
  `IllegalArgumentException` with a clear message.

## 5. Validation and `ConnectorConfig`

Before calling `connect`, GenSynth resolves the flow's values against your fields:

1. empty values (`null` or blank text) are replaced by the field default;
2. values are converted to the field type (`"5672"` → `5672L`, `"true"` → `true`);
3. required fields, select options and min/max limits are checked.

If anything is wrong, the flow does not connect and shows the errors (e.g.
`Invalid connector configuration: Host is required; Port must be at most 65535`). The same rules
run in the UI while the user types, so most mistakes never reach your plugin.

In `connect`, read the values with the typed getters. An optional field without a value is
**absent**: use the overloads with a fallback.

```java
String host = config.getString("host");          // required: never null
int port = config.getInt("port", 1883);          // fallback only if absent
String clientId = config.getString("clientId", "gensynth-" + context.flowName());
```

Keys that are not declared as fields are ignored.

## 6. Lifecycle

```
Group started ──► connect(config, context) ──► session.send(...) × N ──► session.close() ◄── Group stopped/paused
                       (once per flow)            (once per message)
```

- **`connect`** runs when the flow's group starts. Open the connection, declare/verify the
  destination if your technology needs it, and fail fast: if it throws, the flow is marked as
  failed with your exception message, and the rest of the group keeps working.
- **`send`** runs once per generated message (one message every *N* ticks of the simulation clock).
- **`close`** runs when the group stops, pauses, or the flow is deleted. Release everything
  and never throw for an already closed connection.
- If the user changes the connection fields while the group runs, they apply on the next start.

`ConnectorContext` gives you:

| Method | Use |
|---|---|
| `flowName()` | Naming: client ids, connection names, file names. |
| `groupName()` | Naming or grouping. |
| `outputDirectory()` | Folder of the current simulation session, for connectors that write files. |

## 7. Delivery semantics (important)

GenSynth shows, for every flow, how many messages were **sent** and how many **failed**:

- `send` **returns normally** → the message counts as **sent**;
- `send` **throws** → the message counts as **failed** and the flow shows the error.

So `send` must only return once the technology has really **accepted** the message, and
**confirmed** it when the technology supports confirmations:

| Technology | Do | Avoid |
|---|---|---|
| RabbitMQ | publisher confirms (`confirmSelect` + `waitForConfirms`), `mandatory` publish | fire-and-forget `basicPublish` |
| Kafka | `producer.send(record).get(timeout)` | a callback that only logs errors |
| MQTT | QoS ≥ 1 and wait for the delivery token | QoS 0 if users expect "sent" to mean delivered |
| HTTP | check the response status; throw on non-2xx | ignoring the response |
| TCP/UDP | throw on I/O errors (UDP cannot confirm delivery; document it in the tooltip/description) | swallowing exceptions |

Always use **timeouts**: a `send` that blocks forever stalls its flow (and, in sequential groups,
the whole group).

## 8. Threading

- Each flow has its **own session**. GenSynth **never calls `send` on the same session from two
  threads at the same time**, so sessions do not need to be thread-safe.
- In a *Parallel* group every flow sends from its own thread; in a *Sequential* group one sender
  thread sends the messages of all flows in order. Either way the rule above holds.
- Different sessions of your plugin may run concurrently. Do not share mutable state between
  sessions through static fields.

## 9. Sandbox and restrictions

When a plugin is imported, GenSynth validates it before installing:

1. it must be a valid JAR;
2. it must contain `META-INF/services/com.gensynth.plugin.api.ConnectorPlugin`;
3. its bytecode must not call blocked APIs: `Runtime.exec/halt/exit`, `ProcessBuilder.start`,
   `System.exit`, creating `ServerSocket`, `DatagramSocket`, `FileOutputStream` or
   `RandomAccessFile`, and `Files.write/delete/move/create*/newOutputStream`;
4. `info()` and `fields()` must load within 5 seconds and be valid (no duplicated keys);
5. a plugin with the same `id@version` is overwritten.

Installing restarts GenSynth. Only one version of each plugin `id` is kept; previous ones are
moved to `core/plugins/backup/`.

## 10. Versioning

`PluginApi.VERSION` (currently **1.0**) is the version of the plugin API. Within a major version
the API only grows backward-compatibly (new default methods, new field types), so a plugin built
for 1.0 keeps working with any 1.x GenSynth. Plugins built for the legacy pre-release API
(`ConnectorPluginProvider`) are rejected with a message asking to rebuild them.

## 11. Testing

Plugins can be tested without GenSynth and without a running broker:

```java
@Test
public void declaresDocumentedFieldsInOrder() {
    List<ConnectorField> fields = new MyConnectorPlugin().fields();
    assertEquals(List.of("host", "port", "topic"), fields.stream().map(ConnectorField::getKey).toList());
    assertTrue(fields.stream().noneMatch(f -> f.getTooltip().isBlank()));
}

@Test
public void requiresTheTopic() {
    ConnectorConfigException error = assertThrows(ConnectorConfigException.class,
        () -> ConnectorConfig.resolve(new MyConnectorPlugin().fields(), Map.of("host", "broker")));
    assertEquals(List.of("Topic is required"), error.getErrors());
}
```

`ConnectorConfig.resolve(fields, rawValues)` is exactly what GenSynth runs before `connect`, so
you can also build a real `ConnectorConfig` and test the code that reads it. For the connection
itself, prefer an integration test against a local broker (e.g. a Docker container).

## 12. Packaging and installing

1. `mvn package` → `target/<artifact>-<version>.jar`.
2. In GenSynth: **Connectors → Import plugin**, drop the JAR, check the validation log
   (it shows the plugin id, API version and number of fields) and install.
3. GenSynth restarts and the connector appears in the connector selector of the flows.

Developers can also copy the JAR into GenSynth's `core/plugins/` folder and restart; the API
compatibility check still applies.

## 13. Checklist

- [ ] One class implements `ConnectorPlugin`, with a public no-argument constructor.
- [ ] Registered in `META-INF/services/com.gensynth.plugin.api.ConnectorPlugin`.
- [ ] `gensynth-plugin-api` has `provided` scope; your client library is `provided` (if in
      `lib/shared`) or shaded into the JAR.
- [ ] `info()`: stable `id`, plugin `version`, one-sentence `description`.
- [ ] `fields()`: logical order, a tooltip on every field, `password` for secrets, required only
      when needed, sensible defaults.
- [ ] Cross-field rules checked at the start of `connect` with clear messages.
- [ ] `send` returns only when the message is accepted/confirmed and throws otherwise, with timeouts.
- [ ] `close` releases everything and never throws for an already closed session.
- [ ] No blocked APIs; no shared mutable static state.
- [ ] Unit tests for the fields and the configuration rules.
